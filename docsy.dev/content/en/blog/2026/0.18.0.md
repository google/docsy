## {{% _param BREAKING %}} Docsy has a new home: `docsy/docsy` {#org-move}

Docsy, created by Google and open sourced in 2018, is now a **[Linux
Foundation][]** project, as [announced][oss-eu-2026] by [Erin McKean][] at the
_Open Source Summit EU_ on October 7, 2026.

The project repositories have moved into their new [`docsy`][docsy-org] GitHub
organization:

- [github.com/docsy/docsy][repo], the main project monorepo
- [github.com/docsy/docsy-example][example-repo]

While GitHub redirects the old URLs, Hugo module paths don't follow redirects.
It is good practice to adopt the new canonical paths everywhere.

### Actions {#org-move-actions}

{{% _param BREAKING %}} **Applies if** you import Docsy as a Hugo module.

1. Run `hugo mod get github.com/docsy/docsy/theme@v0.18.0`.
2. In your site config, change the theme's import path from
   `github.com/google/docsy/theme` to `github.com/docsy/docsy/theme`, whether
   it's listed under `module.imports` or under `theme`; re-key any
   `module.replacements` entry, `HUGO_MODULE_REPLACEMENTS` value, or `go.mod`
   `replace` directive the same way.
3. Run tidy and pack:
   - `hugo mod tidy`, which drops the old `require` line (and `hugo mod vendor`,
     if you vendor modules)
   - `hugo mod npm pack`, which regenerates the dependency entries Docsy's
     module contributes to `package.json`, now keyed by the new path, and their
     checksum

{{% _param CLEANUP %}} **Applies if** you install Docsy from GitHub through npm,
a git submodule, or a clone; or your docs link to the old Docsy `google`
organization.

1. Re-point your installation to `docsy/docsy`:
   - **npm**: change the `docsy` spec in `package.json` from `google/docsy` to
     `docsy/docsy`, then run `npm install` and, as after every install of the
     GitHub package, `npm run install:theme-deps --prefix node_modules/docsy`.
   - **Submodule**: run
     `git submodule set-url themes/docsy https://github.com/docsy/docsy.git` and
     commit the updated `.gitmodules`.
   - **Clone**: run
     `git -C themes/docsy remote set-url origin https://github.com/docsy/docsy.git`.
2. Update any documentation URLs, replacing the `google` org with `docsy` for
   links to the Docsy and `docsy-example` repositories.

The [`@docsy/theme`][npm-package] npm package is unaffected.

For the generic update procedure, which assumes the new path, see [Update
Docsy][].

## {{% _param BREAKING %}} / {{% _param NEW %}} Plugins {#plugins}

Docsy 0.18 introduces [**plugins**][ug-plugins]: optional scripts that you
configure from site configuration, each on its own `params.docsy.plugins` entry.
Four of Docsy's scripts ship as plugins:

- [Mermaid](#mermaid)
- [MarkMap](#markmap)
- [Tab persistence][ug-tabpane]
- [Click-to-copy][ug-click-to-copy]

On a plugin's entry, you can:

- Turn it on or off
- Pin its dependency's version
- Pass its settings

You can also [add a script of your own][ug-plugin-authoring] (experimental).

### Actions {#plugins-actions}

{{% _param BREAKING %}} **Applies if** your project has
`layouts/_partials/algolia/head.html` or
`layouts/_partials/algolia/scripts.html`, the override paths
[documented][ug-algolia] before 0.18 but never read. The first now works as
documented; the second moved to `layouts/_partials/scripts/algolia.html`.

- Review your copy, now live, or remove it; move the second to its new path.

{{% _param BREAKING %}} **Applies if** you override `scripts.html`.

- Take the current file, now a dispatcher over `scripts/*.html` sub-partials,
  and re-apply your change to the sub-partial it belongs to.

{{% _param BREAKING %}} **Applies if** you disabled tab persistence by shipping
an empty `static/js/tabpane-persist.js`. The file moved, so the copy is ignored
and persistence is back on.

- Set `enable: false` on the [`tabpane-persist` entry][ug-plugins] and remove
  the file.

{{% _param BREAKING %}} **Applies if** you had `params.docsy` settings before
upgrading. Docsy now [reserves it for theme settings][ug-plugins-warnings].

- Move your settings to another key, and update the templates that read them.

{{% _param NEW %}} **Applies if** you want a script of your own.

- [Add an entry and the files it names][ug-plugin-authoring] (experimental).

{{% _param CLEANUP %}} **Applies if** you set
`params.disable_click2copy_chroma`, deprecated.

- Set `enable: false` on the [`click-to-copy` entry][ug-plugins] and remove the
  old key.

## {{% _param BREAKING %}} Mermaid

Mermaid is now a [plugin](#plugins): its [settings][mermaid-settings] and
[version pin][mermaid-version] live on its `params.docsy.plugins.mermaid` entry.

### Actions {#mermaid-actions}

{{% _param BREAKING %}} **Applies if** you set anything under `params.mermaid`:
the build fails.

- Move each setting onto the [`mermaid` entry][ug-plugins], then delete
  `params.mermaid`. By key:
  - `version`: move to the entry's `version`, only if you had overridden the
    theme's [pin][mermaid-version], and as a plain `X.Y.Z` string: a [range or
    operator][ug-plugins-warnings] now fails the build.
  - `enable`: delete it.
  - Mermaid settings (`theme`, `flowchart.diagramPadding`, …): move to the
    entry's [`options` string][mermaid-settings]. Settings that 0.17 dropped
    (`htmlLabels`, most `class.*` settings) or misread (`secure`,
    `flowchart.htmlLabels`) now take effect, so rendering may change.

{{% _param BREAKING %}} **Applies if** you pin a Mermaid version below
{{% param mermaidMinVersion %}}. Diagrams no longer render: Docsy now starts
Mermaid through its `run()` API.

- Remove your pin to take Docsy's [default][mermaid-version], Mermaid
  {{% param mermaidVersion %}}.

{{% _param BREAKING %}} **Applies if** you customized `scripts/mermaid.html`.
Your copy is ignored; its content splits three ways.

- Re-apply a changed pin check to the companion partial
  `scripts/plugins/mermaid.html`.
- Move runtime changes (start, dark mode) to `assets/js/plugins/mermaid.js`
  (overriding it is experimental).
- Move settings to the entry's `options`.

{{% _param BREAKING %}} **Applies if** your Content Security Policy allowed
Mermaid's inline script by hash.

- Allow `'self'` for the deferred same-origin script that replaces it;
  `cdn.jsdelivr.net` is still needed for the library.

{{% _param NEW %}} **Applies if** you want to try Mermaid 12 early
(experimental).

- Set the entry's `version` to a 12.x release; for what to expect and where to
  report, see the user guide's [Mermaid 12][ug-mermaid-12] section.

## {{% _param BREAKING %}} MarkMap

MarkMap is now a [plugin](#plugins), and it loads only on pages that have a mind
map, where enabling it used to load it on every page. Its autoloader is fetched
at build time and served from your site, so no inline script remains to hash in
a Content Security Policy.

### Actions {#markmap-actions}

{{% _param BREAKING %}} **Applies if** you set anything under `params.markmap`.
The build fails until the namespace is gone, empty table or map included.

- Move each setting onto the `markmap` entry under
  [`params.docsy.plugins`][ug-plugins], then delete `params.markmap`. By key:
  - `enable`: move to the entry's `enable`.
  - `version`: move to the entry's `version`, only if you had overridden the
    theme's [pin][markmap-version]; a range or operator now fails the build, as
    for [Mermaid](#mermaid-actions).

{{% _param BREAKING %}} **Applies if** you relied on `params.markmap.enable`
loading MarkMap on every page, or produce MarkMap markup other than through a
`markmap` fence on the page itself (tabs, included files, section print views).
The `markmap` entry loads MarkMap only on pages Docsy detects a fence on, so
those maps stay code blocks with a green build.

- For the one-line remedy (experimental) and the affected authoring paths, see
  [When a MarkMap doesn't render][markmap-not-rendering].

{{% _param BREAKING %}} **Applies if** your own scripts call MarkMap's API
(`window.markmap.autoLoader`, for example from a body-end hook). The autoloader
is now a deferred script.

- [Wait for `DOMContentLoaded`][markmap-activating] before calling it.

{{% _param BREAKING %}} **Applies if** you have a project-wide
`render-codeblock.html` hook. It no longer sees `markmap` fences: Docsy now
ships `render-codeblock-markmap.html`, which takes precedence for that language,
as the mermaid, math, and chem hooks already do for theirs.

- Move any `markmap`-specific handling into an override of
  `render-codeblock-markmap.html`.

{{% _param BREAKING %}} **Applies if** your build has no network access or
restricts Hugo's remote fetches. MarkMap builds now fail without
`cdn.jsdelivr.net`: the autoloader is fetched at build time instead of by the
browser.

- For the offline remedy, see [MarkMap version][markmap-version].

{{% _param BREAKING %}} **Applies if** you customized `scripts/markmap.html`.
Your copy is ignored; its content splits two ways.

- Re-apply a changed pin check to the companion partial
  `scripts/plugins/markmap.html`.
- Move autoloader settings and the map-sizing style to
  `assets/js/plugins/markmap.js` (overriding it is experimental).

{{% _param BREAKING %}} **Applies if** your Content Security Policy allowed
MarkMap's inline script or style by hash. The autoloader now loads as a
same-origin script with no inline block, and the map-sizing style is inserted by
script, so a stale style hash shrinks maps silently.

- Allow `'self'` for the autoloader, and keep allowing both `cdn.jsdelivr.net`
  and `unpkg.com`: the autoloader still probes both for MarkMap's libraries.
- Carry the map-sizing rule in a site stylesheet instead of a style hash.

## {{% _param BREAKING %}} / {{% _param CLEANUP %}} jQuery dropped {#jquery}

Docsy's own scripts now use standard DOM APIs, so the theme no longer loads
[jQuery][]: the jQuery script element is gone from the page `head`, and
`window.jQuery` and `$` are no longer available to site scripts.

What every page gains: the removed element was a render-blocking request to
`code.jquery.com` in the page `head`, so pages now start rendering without
waiting on a third-party origin; a first visit fetches about 30 KB (compressed)
less; and your site's third-party footprint shrinks by one host, one fewer
exception for sites that aim to serve only local resources.

No action is needed if your project's own scripts don't use jQuery; to check,
search them (`assets/`, `layouts/`, `static/`, and any inline `<script>` or
page-bundle JS under `content/`) for `$(` or `jQuery`, and JS files for `$.` too
(in layouts, `$.` is ordinary Hugo template syntax, so inspect only their inline
`<script>` blocks).

### Actions {#jquery-actions}

{{% _param BREAKING %}} **Applies if** your own scripts rely on the jQuery that
Docsy loaded. Either:

- Convert them to [standard DOM APIs][mdn-dom]; for jQuery-to-native
  equivalents, see [You Don't Need jQuery][ydnj].
- Keep jQuery by loading it yourself: add the script element for your chosen
  jQuery release from [releases.jquery.com][jquery-releases] (Docsy loaded
  3.7.1; pin the same to keep your scripts' behavior unchanged) to a
  [hooks/head-end.html partial][head-end] in your project.

{{% _param CLEANUP %}} **Applies if** your Content Security Policy allows
`code.jquery.com`.

- Remove it from `script-src`, unless you load jQuery yourself.

After upgrading, spot-check your key pages -- including a diagram page, if your
site has them -- with the browser console open, and exercise interactive
features such as search: a `$ is not defined` or similar jQuery-is-missing error
indicates remaining jQuery-dependent code.

## {{% _param BREAKING %}} / {{% _param NEW %}} `llms.txt`: doc-rooted sites and agent discovery {#llms-txt}

[Doc-rooted sites][ug-doc-rooted] can now publish [`llms.txt`][ug-llms-txt] from
their docs landing page, the page published at the site root. Pages of sites
publishing `llms.txt` now also carry the [llms.txt proposal][llmstxt]'s v2
[discovery link][ug-discovery]. Agent support as a whole is still
[experimental][].

Two more changes apply to every site. The line after a Markdown version's title
and description now reads `Site llms.txt`, linking the current site's file, and
is omitted when the site publishes none. And the theme's `llms.txt` template is
now `all.llms.txt` (was `index.llms.txt`), so that section pages can render it;
a project's generic LLMS template now renders the root file too.

### Actions {#llms-txt-actions}

{{% _param BREAKING %}} **Applies if** your project has a generic `all.llms.txt`
or `list.llms.txt` template that must not serve as the root file.

- Add a template that takes precedence for the root file: `home.llms.txt` on a
  regular site, `TYPE/section.llms.txt` on a doc-rooted one, where _`TYPE`_ is
  the docs landing page's type, `docs` unless it sets one; for the template's
  shape, see [customize output][ug-llms-customize].

{{% _param NEW %}} **Applies if** your site is doc-rooted and you want an
`llms.txt`.

- [Add `LLMS` to the docs landing page's `outputs`][ug-doc-rooted], per
  language; to customize the file, see [customize output][ug-llms-customize].

{{% _param NEW %}} **Applies if** your site publishes `llms.txt` and overrides
`head.html`.

- Add the [discovery link][ug-discovery] to your copy.

## Other notable changes

- **Phone navbar**: with the light/dark mode menu enabled and a navbar menu that
  scrolls sideways, phone pages no longer render zoomed out.

For this and all other changes, see the [0.18.0][] release page.

## For maintainers

Changes in this section affect Docsy maintainers and contributors; the first two
also make the theme you depend on harder to compromise. The changelog's
[For-maintainers list][CL@0.18.0] itemizes them.

- **Workflow security**: PRs into `main` are now gated on a [zizmor][] [scan of
  the GitHub Actions workflows][maintainer-notes-zizmor].
- **Dependency updates**: Renovate's [GitHub Actions
  bumps][maintainer-notes-deps] now come from GitHub Releases and are
  SHA-pinned.
- **Branch model**: the release procedure is now [written down][branch-model]
  against the rulesets that enforce it.
- **Link cache**: docsy.dev's committed link cache now follows the
  [link-cache][] package's format and prune rule, and a [scheduled
  workflow][maintainer-notes-links] proposes refreshes as PRs.

### {{% _param FAS square-check primary %}} Sanity checks

In addition to the [generic site checks][check], for this release:

- [ ] For a Hugo module, `hugo mod graph` lists `github.com/docsy/docsy/theme`
      at the version you pinned (or your replacement for it) and no
      `github.com/google/docsy` entry remains. If you re-pointed an

      `docsy/docsy`, or `git -C themes/docsy remote -v` shows the new URL.
- [ ] With the browser console open, your key pages and search show no
      `$ is not defined` or similar error; see [jQuery](#jquery).
- [ ] If your site uses MarkMap, tab persistence, or click-to-copy, each still
      works on every page that had it; for the pages most likely to lose a map,
      see the [MarkMap actions](#markmap-actions).
- [ ] If your site uses Mermaid, diagrams render in light and dark mode; see
      [Mermaid](#mermaid).
- [ ] If your project has any LLMS template, the root `llms.txt` renders from
      the [one you intend for it](#llms-txt-actions).
- [ ] The build reports no `params.mermaid` or `params.markmap` error and no
      `docsy-c2c-legacy` warning (settings left under the old keys), and no
      [`docsy-config` warning][ug-plugins-warnings] (a malformed `params.docsy`
      entry).
- [ ] If you pinned a Mermaid or MarkMap version, the build runs without a
      `*-floating-version` warning and diagrams render at that version.
- [ ] If you override the root `baseof.html`, it includes `scripts.html` with
      [`partial`, not `partialCached`][update-overrides].
- [ ] If you diff built output, investigate only differences beyond these
      expected ones:
  - [ ] The jQuery script element is gone from `head`.
  - [ ] Mermaid's inline module script, and MarkMap's inline script and style,
        are replaced by deferred same-origin entries; the plugin script tags
        moved.
  - [ ] On pages that use the root `baseof.html`, script tags follow each page's
        own needs (page-gated diagrams and math, a per-page `body-end` hook)
        rather than the first-rendered page's.
  - [ ] On sites publishing `llms.txt`, every page `head` has a
        `rel="describedby"` link (with an overridden `head.html`, once you add
        it: [actions](#llms-txt-actions)), the agent directive's wording
        changed, and each Markdown version carries a `Site llms.txt` line after
        its title and description; a site without `llms.txt` loses that line and
        its separator ([`llms.txt`](#llms-txt)).
