## {{% _param BREAKING %}} Docsy has a new home: `docsy/docsy` {#org-move}

The Docsy repositories moved out of the `google` GitHub organization into their
own: the theme now lives at [github.com/docsy/docsy][repo] and the example site
at [github.com/docsy/docsy-example][example-repo] ([#1992][]). GitHub redirects
the old URLs, so clones, submodules, and `npm install google/docsy` keep
working. The **Hugo module path** changed with the move, though, and module
paths don't follow redirects: 0.18.0 and later are published only as
`github.com/docsy/docsy/theme`, while the old path still resolves 0.17.0 and
earlier.

What this means for your site:

- **If you import Docsy as a Hugo module**, migrate as part of this upgrade:
  1. In your site config, change the theme's import path from
     `github.com/google/docsy/theme` to `github.com/docsy/docsy/theme`, whether
     it's listed under `module.imports` or under `theme`.
  2. Run `hugo mod get github.com/docsy/docsy/theme@v0.18.0`, then
     `hugo mod tidy`.
  3. Remove any `github.com/google/docsy/theme` entries that remain in your
     `go.mod` (`require`) or site config (`module.replacements`).
- **If you install Docsy from GitHub through npm, a git submodule, or a clone**,
  re-point the reference to `docsy/docsy`. For a submodule, run
  `git submodule set-url themes/docsy https://github.com/docsy/docsy.git` and
  commit the updated `.gitmodules`; for a plain clone,
  `git -C themes/docsy remote set-url origin https://github.com/docsy/docsy.git`.
  The [`@docsy/theme`][npm-package] npm package is unaffected.
- **If you pin a commit rather than a release**, only commits made after the
  move resolve under the new module path; pin a tag or a post-move commit.

The generic update procedure ([Update Docsy][update-docsy]) already uses the new
path; the migration steps above are specific to this release.

## {{% _param BREAKING %}} Docsy no longer loads jQuery {#jquery}

Docsy's own scripts now use standard DOM APIs, so the theme no longer loads
[jQuery][]: the jQuery script element is gone from the page `head`, and
`window.jQuery` and `$` are no longer available to site scripts ([#1436][]).
Each page makes one fewer third-party request, and sites aiming to serve only
local resources have one fewer exception to manage.

What this means for your site:

- **No action needed** if your project scripts don't use jQuery. To check,
  search your project's own scripts (`assets/`, `layouts/`, `static/`) for `$(`
  or `jQuery` -- and in JS files, `$.` too (in layouts that token is ordinary
  Hugo template syntax, but do eyeball any inline `<script>` blocks there).
- **If you override a converted file**, [review your override against the new
  theme version][update-overrides]. The files that changed:
  - `assets/js/base.js`, `search.js`, `offline-search.js`, `plantuml.js`, and
    `markmap.js` (now under `plugins/`), plus
    `layouts/_partials/scripts/mermaid.html`: override copies made before 0.18
    still expect the jQuery that Docsy no longer loads.
  - `layouts/_partials/head.html`: an old copy keeps loading jQuery -- and can
    mask stale copies of the files above from the console check below.
- **If your own scripts rely on the jQuery that Docsy loaded**, either:
  - Convert them to standard DOM APIs -- for equivalents, see [You might not
    need jQuery][], or
  - Keep jQuery by loading it yourself: add the following script element to a
    [hooks/head-end.html partial][head-end] in your project:

    ```html
    <script
      src="https://code.jquery.com/jquery-3.7.1.min.js"
      integrity="sha512-v2CJ7UaYy4JwqLDIrZUI/4hqeoQieOmAZNXBeQyjo21dadnwR+8ZaIJVT8EE2iyI61OV8e6M8PP2/4hpQINQ/g=="
      crossorigin="anonymous"
    ></script>
    ```

After upgrading, spot-check your key pages -- including a diagram page, if your
site has them -- with the browser console open, and exercise interactive
features such as search: a `$ is not defined` or similar jQuery-is-missing error
indicates remaining jQuery-dependent code.

[#1436]: https://github.com/docsy/docsy/issues/1436
[head-end]: /docs/content/lookandfeel/#add-code-to-head-or-before-body-end
[jQuery]: https://jquery.com/
[update-overrides]: /docs/update/#update-overrides

## {{% _param BREAKING %}} Plugins

Docsy 0.18 introduces [**plugins**][ug-plugins] (`params.docsy.plugins`), a
registry for loading site scripts without layout overrides, and moves Mermaid,
MarkMap, tab persistence and click-to-copy onto it ([#2789][]). Each entry takes
`enable`, `version` and the plugin's own `options`; you can also [add a plugin
of your own][ug-plugin-authoring] (experimental). Mermaid's migration has
[its own section](#mermaid).

### Registry and overrides {#plugins-registry}

- **If you set `params.disable_click2copy_chroma`**: it is deprecated and
  honored with a build warning for this release; set `enable: false` on the
  `click-to-copy` entry under [`params.docsy.plugins`][ug-plugins] instead, then
  remove it.
- **If you override a moved file**, [review and move your
  override][update-overrides]; old copies are silently ignored:
  - `assets/js/markmap.js` and `assets/js/click-to-copy.js` moved to
    `assets/js/plugins/`.
  - `static/js/tabpane-persist.js` moved to
    `assets/js/plugins/tabpane-persist.js`.
  - `scripts/markmap.html` and `scripts/mermaid.html` are gone; each plugin's
    companion partial, `scripts/plugins/markmap.html` and
    `scripts/plugins/mermaid.html`, takes its role (for a customized
    `scripts/mermaid.html`, see [Mermaid](#mermaid-plugin)).
  - Algolia's `algolia/head.html` and `scripts/algolia.html` are now partials:
    overrides at those paths, previously ignored because the originals were
    named templates, now take effect.
- **If you override `scripts.html`**, a pre-0.18 copy fails the build (it reads
  scripts that have moved); 0.18 also decomposed it into a dispatcher over
  `scripts/*.html` sub-partials, so take the current file and re-apply your
  change to the sub-partial it belongs to.
- **If your site config has a `params.docsy` key of its own**, rename it: Docsy
  now reserves `params.docsy` for theme settings, and a non-map value there
  turns the theme plugins off ([warnings][ug-plugins-warnings]).

### MarkMap

- **If you set anything under `params.markmap`**, the build fails until you move
  each setting onto the `markmap` entry under
  [`params.docsy.plugins`][ug-plugins]: `enable` to the entry's `enable` (to
  keep loading MarkMap on every page, set the flag described under [When a
  MarkMap doesn't render][markmap-not-rendering]); `version` to the entry's
  `version`, only if you had overridden the theme's pin ([MarkMap
  version][markmap-version]). Ranges are no longer accepted; pin an exact
  version ([warnings][ug-plugins-warnings]).
- **If you produce MarkMap markup other than through a `markmap` fence on the
  page itself, or print sections that contain one**: Docsy's render hook no
  longer flags those pages for MarkMap. Set the `hasMarkmap` page flag from a
  [`hooks/head-end.html`][head-end] partial (experimental, as part of plugin
  authoring); for the affected authoring paths and the one-line partial, see
  [When a MarkMap doesn't render][markmap-not-rendering].
- **If you have a project-wide `render-codeblock.html` hook**, it no longer sees
  `markmap` fences: Docsy now ships `render-codeblock-markmap.html`, which takes
  precedence for that language, as the mermaid, math, and chem hooks already do
  for theirs.
- **If your build has no network access or restricts Hugo's remote fetches**,
  MarkMap builds now fail without `cdn.jsdelivr.net`: the autoloader is fetched
  at build time instead of by the browser; for the offline remedy, see [MarkMap
  version][markmap-version].

## {{% _param BREAKING %}} Mermaid

Mermaid is now a [plugin](#plugins): its settings live on one registry entry,
Docsy starts it through Mermaid's `run()` API from a deferred script of its own,
and the version pin is exact. Sites can also try Mermaid 12 ahead of its
official support.

### Now a plugin {#mermaid-plugin}

- **If you set anything under `params.mermaid`**, the build fails until you move
  each setting onto the `mermaid` entry under
  [`params.docsy.plugins`][ug-plugins]. By key:
  - `version`: move to the entry's `version`, only if you had overridden the
    theme's pin ([Mermaid version][mermaid-version]).
  - `enable`, unused since Docsy 0.9.0: delete it.
  - Mermaid settings (`theme`, `flowchart.diagramPadding`, …): move to the
    entry's `options` string ([Mermaid settings][mermaid-settings]). Settings
    the old map dropped (`htmlLabels`, most `class.*` options) or mangled
    (`secure`, `flowchart.htmlLabels`) now take effect, so rendering may change.
- **If you pin a Mermaid version other than Docsy's**: below Mermaid 10 no
  longer renders (Docsy now starts Mermaid through `run()`), and a range (`~11`,
  `^11.17.0`) is no longer accepted; pin an exact version
  ([warnings][ug-plugins-warnings]).
- **If you customized `scripts/mermaid.html`**, your copy is ignored; the
  content splits three ways: the pin check stays in the companion partial
  `scripts/plugins/mermaid.html`, the runtime (start, dark mode) moves to
  `assets/js/plugins/mermaid.js`, and settings move to the entry's `options`.
- **If your Content Security Policy allowed Mermaid's inline script by hash**,
  allow the deferred same-origin entry that replaces it (`'self'`);
  `cdn.jsdelivr.net` is still needed for the library.

### Early Mermaid 12 support {#mermaid-12}

Docsy 0.18 officially supports Mermaid 11 (the default pin), and lets you try
[Mermaid 12][mermaid-12] early: set the entry's `version` to a 12.x release and
diagrams render through the same plugin. Expect Mermaid 12's own defaults (the
ELK layout, the `redux-color` theme and `neo` look on most diagram types), for
which Docsy's dark-mode handling isn't yet tuned, and note that Mermaid 12
requires Safari 17.4 or later. Finalized support, including dark-mode handling,
is planned for 0.19; report what you find on [#2825][].

## Override hygiene {#overrides}

The root `layouts/baseof.html` now includes the scripts partial with `partial`
rather than `partialCached`, so page-gated scripts (diagrams, math) are decided
per page rather than by whichever page rendered first. Docsy's own pages were
never affected; the change removes a latent hazard for sites that extend
page-gated scripts to pages outside the docs and blog sections.

**Applies if** your project overrides the root `baseof.html`: your copy still
carries `partialCached "scripts.html" .`. Mirror the one-line change to
`partial "scripts.html" .` as part of your [override review][update-overrides],
and expect no rendered difference.

## For maintainers

Changes in this section affect Docsy maintainers and contributors, not consuming
sites. The changelog's [For-maintainers list][CL@0.18.0] itemizes them.

- **Workflow security analysis**: [zizmor][] now scans the repository's GitHub
  Actions workflows on every change, at its pedantic persona, and a finding on
  changed lines blocks the PR; the workflows were brought to zero findings.
- **Dependency updates**: Renovate's configuration moved to JSONC, GitHub
  Actions bumps are looked up as releases and pinned by SHA in their own PRs,
  and the schedule runs on UTC; the [maintainer notes][maintainer-notes-deps]
  describe the cadence and the guards.
- **Branch model**: the [branch model][branch-model] page now states the
  per-branch invariants, the tag rulesets, and the release procedures the `main`
  ruleset allows.
- **Link cache**: docsy.dev's committed link cache is an owned JSONC file, and a
  weekly workflow re-verifies its oldest entries.

## {{% _param FAS rocket primary %}} Upgrade to 0.18.0 {#upgrade}

Follow [Update Docsy][] and as you do:

{{< comment >}} Deliberate repeat of the warning from
[Breaking changes](#breaking-changes), for readers who jump straight to this
section. {{< /comment >}}

- :warning: Respect the [order of steps][] to avoid breaking your build.
- Re-point your install at Docsy's [new home](#org-move) **as** you update the
  theme: the 0.18.0 module path is `github.com/docsy/docsy/theme`.
- Use these versions:[^vers-note]
  - **[Docsy][update-theme]**: [0.17.0][] -> [0.18.0][]
  - **[Hugo][update-hugo]**:
    [{{% param hugoSupportedVersion %}}][hugo-supported-version] (unchanged;
    theme minimum [0.160.1][])
  - **[Node][update-node]**: LTS 24 (unchanged)
- Remember to [review your theme overrides][update-overrides]: this release
  reworks theme files that sites commonly override, including `head.html`, the
  root `baseof.html`, `scripts.html` and its sub-partials, and the script assets
  listed under [jQuery](#jquery), [plugins](#plugins) and [Mermaid](#mermaid).

[^vers-note]:
    Matches `docsy.dev`'s tested Hugo pin and the theme's declared minimum Hugo
    version. Later Hugo or Node versions may work; see the [official support
    policy][].

### {{% _param FAS square-check primary %}} Sanity checks

In addition to the [generic site checks][check], for this release:

- [ ] Your theme reference points at `docsy/docsy`: for a Hugo module,
      `hugo mod graph` lists `github.com/docsy/docsy/theme` at 0.18.0 and no
      `github.com/google/docsy` entry remains; for a submodule or clone,
      `git -C themes/docsy remote -v` shows the new URL.
- [ ] With the browser console open, your key pages and search show no
      `$ is not defined` or similar error; see [jQuery](#jquery).
- [ ] If your site uses MarkMap, tab persistence or click-to-copy, each still
      works; a build error naming `params.markmap`, or a `docsy-config` warning,
      points at a setting still under the old keys; see
      [registry and overrides](#plugins-registry).
- [ ] If your site uses Mermaid, diagrams render, in light and dark mode; a
      build error naming `params.mermaid` points at settings still under the old
      key; see [Mermaid](#mermaid).
- [ ] If you pinned a Mermaid or MarkMap version, the build accepts it (exact
      versions only) and diagrams render at it.
- [ ] If you override the root `baseof.html`, it includes `scripts.html` with
      `partial`, not `partialCached`; see [override hygiene](#overrides).
- [ ] If you diff built output, expect the jQuery script element to be gone from
      `head`, Mermaid's inline module script to be replaced by a deferred
      same-origin entry, and the plugin script tags to move; investigate only
      unexplained differences.
